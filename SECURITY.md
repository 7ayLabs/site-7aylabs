# Security policy

## Reporting a vulnerability

Report it privately, either way:

- **GitHub:** open the repository's Security tab and choose "Report a
  vulnerability". The report is visible only to the maintainers.
- **The site:** send it through <https://7aylabs.com/contact> with the topic
  set to "Security".

Please do not open a public issue or pull request for a security problem.

Include what you can:

- what is affected (a URL, an API route, a file in this repository);
- how to reproduce it, step by step;
- what an attacker could do with it;
- whether it has been disclosed anywhere else.

You will get an acknowledgement within 3 working days and an assessment
within 10. We will keep you informed while we fix it and tell you when the
fix is live. Please give us a reasonable chance to fix the problem before
you publish details; we are glad to credit you if you would like that.

## Scope

In scope:

- the code in this repository;
- the sites it serves: `7aylabs.com`, `www.7aylabs.com` and
  `test.7aylabs.com`, including their `/api/*` routes;
- the build and deploy pipeline defined in `.github/` and `scripts/`.

Out of scope:

- other 7ayLabs products and domains (report those the same way and
  we will route them);
- denial of service by volume, and anything that needs sending large
  amounts of traffic;
- social engineering of staff, and physical attacks;
- findings that need a compromised device or browser on the victim's side;
- reports generated by a scanner with no demonstrated impact (missing
  headers on error pages, version banners and the like);
- services run by third parties (the CDN, the registry, the hosting
  provider), except where our configuration of them is the problem.

## Testing rules

- Use `test.7aylabs.com` where you can. It runs the same code as production.
- Do not read, change or delete data that is not yours. If you reach
  someone else's data, stop and report it.
- Do not submit the contact form in bulk. A handful of test submissions is
  fine; mark them clearly as tests.
- No automated scanning at a rate that would affect other visitors.

Research that follows these rules is welcome, and we will not pursue legal
action over it.

## How the project handles secrets

This repository is public. It contains no credentials, host addresses or
tokens, and must never. Runtime configuration lives in files on the host
(mode 600) and in GitHub Actions secrets. Every push is scanned for leaked
secrets (`.gitleaks.toml`, the `secret-scan` job in CI). If you find a
secret in the history, report it as a vulnerability.

## Supported versions

Only the version currently deployed from `main` is supported. Fixes are
released by deploying; there are no maintained older versions.
